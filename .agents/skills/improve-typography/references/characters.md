# Characters, punctuation, and spaces

Which character to use: quotes, apostrophes, dashes, ellipses, symbols, nonbreaking spaces, soft hyphens, ligatures. Read when writing or editing copy, or checking authored text and HTML entities.

From Butterick’s Practical Typography. Each heading links to the source page.

### [Straight and curly quotes](https://practicaltypography.com/straight-and-curly-quotes.html)

- Use curly quotes (‘ ’ “ ”); “straight quotes should never, ever appear in your documents.”
- Exception: use straight quotes for foot and inch marks.
- Fix straight quotes in pasted or imported text.
- Fix quotes first, then correct apostrophes at the start of words (’70s), since the quote fix will undo them.
- Fix old double quotes made of two single quotes (' ') or two grave accents (``) the same way.
- On the web, specify a non-ASCII encoding such as UTF‑8 when entering curly quotes directly.
- Use a CMS plugin or proven JavaScript converter for curly quotes; don’t write your own converter.
- If using the HTML `q` tag, set a `lang` attribute (e.g., `lang="en"`) on a parent element; note it doesn’t handle apostrophes.
- Straight quotes are acceptable in email.
- Don’t use quotation marks for emphasis; use bold or italic.
- Never convert straight quotes and backticks in software code to curly quotes.

### [One space between sentences](https://practicaltypography.com/one-space-between-sentences.html)

- Always put exactly one space between sentences.
- More generally, put exactly one space after any punctuation.
- Exception: in a monospaced (typewriter-style) font, two spaces are tolerable, though still unnecessary.
- Don’t let personal taste or colleagues’ habits override the rule.
- Exception: if your boss will fire you for not using two spaces, let it go.
- When advocating better typography at work, start with something less provocative (e.g., eradicating all caps) and lead by example, not by decree.

### [Question marks and exclamation points](https://practicaltypography.com/question-marks-and-exclamation-points.html)

- Use more question marks: recast topic sentences as questions to make them simpler and pithier.
- Budget one exclamation point for any document longer than three pages; if you must use it, use it wisely.
- Never use more than one exclamation point in a row.

### [Emoticons and emoji](https://practicaltypography.com/emoticons-and-emoji.html)

- Emoticons and emoji are acceptable in casual writing such as email and texts.
- Don’t use them in non-casual settings (e.g., a résumé).
- Don’t overuse them; if you punctuate every sentence with :-), learn to write better.
- Don’t count on emoji nuance, since they render differently across devices and platforms.
- Orient sideways emoticons to match your writing system: in English, :-) not (-:.

### [Semicolons and colons](https://practicaltypography.com/semicolons-and-colons.html)

- Use a semicolon instead of a conjunction to join two sentences.
- Don’t use a semicolon to connect a subordinate clause to a sentence; use a comma.
- Don’t put a semicolon before a conjunction; use a comma, no punctuation, or start a new sentence.
- Use semicolons to separate list elements that contain internal commas.
- Use a colon to connect the introduction of an idea and its completion.
- Don’t mix up semicolons and colons.
- Consult Garner’s Modern English Usage for exceptions and details.

### [Paragraph and section marks](https://practicaltypography.com/paragraph-and-section-marks.html)

- Always follow a paragraph mark (¶) or section mark (§) with a nonbreaking space.
- At the start of a sentence, spell out the word instead of using the mark (Section 17200 …).
- Double the mark for multiple references (¶¶, §§).
- Feel free to use these marks outside legal and academic writing.
- Don’t use paragraph marks within a block of text to denote internal paragraphs (archaic); use a first-line indent or space between paragraphs.

### [Parentheses, brackets, and braces](https://practicaltypography.com/parentheses-brackets-and-braces.html)

- Use parentheses for citations and asides, brackets for changes within quoted material, and braces only in technical and mathematical writing.
- Don’t let these marks adopt the formatting (e.g., italic or bold) of the material they surround.
- Exception: if an italic character collides with a roman parenthesis, italicize the parentheses.
- Watch for collisions between roman and bold/italic characters, since kerning doesn’t fix them.

### [Hyphens and dashes](https://practicaltypography.com/hyphens-and-dashes.html)

- Don’t treat hyphens (-), en dashes (–), and em dashes (—) as interchangeable.
- Don’t hyphenate after a prefix (nonprofit, not non-profit).
- Don’t hyphenate phrasal adjectives beginning with an ‑ly adverb (closely held company).
- Don’t hyphenate multipart foreign terms or proper names used as adjectives (habeas corpus appeal, Third Circuit docket).
- Do hyphenate other phrasal adjectives for clarity (listener-supported radio, five-dollar bills); “as a professional writer, you should not” omit them.
- Don’t approximate dashes with two or three hyphens (-- or ---); use real dashes.
- Use the en dash for ranges of values (1880–1912, pages 330–39, Exhibits A–E).
- If you open a range with “from,” pair it with “to,” not an en dash.
- Use the en dash for connections or contrasts between pairs of words (conservative–liberal split, Sarbanes–Oxley Act).
- Use the em dash to break a sentence where a comma is too weak but a colon, semicolon, or parentheses are too strong; it is underused.
- Don’t use a slash (/) where an en dash is correct.
- Use a hyphen, not an en dash, for compound names (Sarbanes-Oxley as a married name).
- Set em and en dashes flush against surrounding text; if em dashes look crushed (especially on screen), add word spaces around them.
- An en dash is an acceptable minus sign in spreadsheets or math expressions.
- In American typography, use em dashes rather than Bringhurst’s spaced en dashes.

### [Ampersands](https://practicaltypography.com/ampersands.html)

- Use ampersands freely when part of a proper name (Fromage & Cracotte LLP).
- Otherwise, treat them like contractions: the more formal the document, the less you use them — “here and there, but not everywhere.”

### [Trademark and copyright symbols](https://practicaltypography.com/trademark-and-copyright-symbols.html)

- Use the real symbols (™ ® ©); don’t use alphabetic approximations like (TM) or (c).
- Put no space between text and a trademark symbol (MegaCorp™).
- Set the copyright symbol in line with text and follow it with a nonbreaking space before the year (© 2026).
- Space the © like a word, since it replaces the word “copyright.”
- Beware automatic substitution of (TM), (R), (c), which can silently turn Section 12(c) into Section 12©.
- Don’t write “Copyright © 2026”; use the word or the symbol, not both.
- Optionally (a preference, not a rule) use nonitalic versions of these marks even next to italic text.

### [Ellipses](https://practicaltypography.com/ellipses.html)

- Use the ellipsis character (…), not three periods or periods separated by spaces.
- Spacing around an ellipsis is up to you; typically put spaces before and after, but remove them if that looks odd.
- If text is on only one side of the ellipsis, use a nonbreaking space on that side.
- If forced to use spaced periods, separate them with nonbreaking spaces, and use nonbreaking spaces on the ends unless there’s text on both sides.
- To indicate interrupted dialogue, prefer the em dash over an ellipsis, except perhaps in fiction or screenplays.

### [Apostrophes](https://practicaltypography.com/apostrophes.html)

- Make apostrophes curly and pointing downward (’).
- Fix apostrophes in text imported from plain-text sources.
- At the start of a word, use an apostrophe, not an opening single quote (’70s, rock ’n’ roll, not ‘70s).
- Don’t put an apostrophe before the s in ’70s.
- For Hawaiian okinas, use an opening single quote (Hawai‘i), not an apostrophe; or omit them, since anglicized spellings (Hawaii) are almost always acceptable.

### [Accented characters](https://practicaltypography.com/accented-characters.html)

- Always render accented characters accurately in proper names; otherwise the name is misspelled.
- Spell naturalized loanwords without accents (naive, melee, coupe) and unnaturalized ones with them (cause célèbre, piña colada); check a dictionary or usage guide.
- Don’t italicize proper names; italicize loanwords only depending on their degree of assimilation (check a guide).
- Ignore the German Eszett (ß) and use ss, following Switzerland’s lead.

### [Foot and inch marks](https://practicaltypography.com/foot-and-inch-marks.html)

- Use straight quotes (' ") for foot and inch marks, not curly ones.
- In HTML, use `&#39;` and `&#34;`/`&quot;` so they aren’t curled.
- True prime marks (′ ″) are fine if your font has them, but straight quotes are the most reliable tool.
- Optionally italicize the straight quotes to better approximate sloped prime marks.
- Within quoted material, keep curly quotes for the quotation and straight marks for the measurement (“She’s 6' 10".”).
- If your font lacks true foot and inch marks, borrow them from another font, matching height and weight.
- Put a nonbreaking space in the middle of a foot-and-inch measurement (6' 10").

### [White-space characters](https://practicaltypography.com/white-space-characters.html)

- Use the right white-space character for each job (word space, nonbreaking space, tab, line break, new paragraph) for control and predictability.
- In HTML, use explicit formatting tags to achieve visible white-space effects.

### [Word spaces](https://practicaltypography.com/word-spaces.html)

- Use exactly one word space at a time; don’t hold down the space bar as a general-purpose white-space dispenser.
- Use a thin space where a word space seems too large (e.g., after the periods in W. A. Dwiggins).
- Don’t add a second space after a sentence; the period already makes the gap look larger.

### [Nonbreaking spaces](https://practicaltypography.com/nonbreaking-spaces.html)

- Put a nonbreaking space before any numeric or alphabetic reference (§ 1782, ¶ 49).
- Also use a nonbreaking space after abbreviated reference marks (Ex. A, Fig. 23), honorifics and titles (Sgt. Rock, Ms. Marvel), and trademark and copyright symbols.
- In HTML source, use the `&nbsp;` escape code so the nonbreaking space is visible and explicit.
- Don’t build larger spaces out of sequences of nonbreaking spaces — “like fixing a flat tire with duct tape.”

### [Tabs and tab stops](https://practicaltypography.com/tabs-and-tab-stops.html)

- For space at the beginning of a paragraph, use a first-line indent, not a tab or spaces.
- For a true tabular layout, use a table.
- In HTML, use tables, or CSS flexbox and grid, for tabular arrangements.

### [Hard line breaks](https://practicaltypography.com/hard-line-breaks.html)

- Use a line break, not a new paragraph, to break a line within the same paragraph (e.g., to balance an awkwardly breaking heading).
- Use line breaks to separate lines of an address.

### [Carriage returns](https://practicaltypography.com/carriage-returns.html)

- Start a new paragraph only for a new paragraph; don’t use empty paragraphs for vertical space. Use space between paragraphs instead.
- Exception: multiple returns are fine for vertical space in emails.

### [Optional hyphens](https://practicaltypography.com/optional-hyphens.html)

- Insert optional (soft) hyphens in words that hyphenation engines break incorrectly (e.g., True~Type), typically jargon, unusual proper names, and trade names.
- In HTML, use `&shy;`; prefer optional hyphens over CSS `hyphens`, which is less well supported.

### [Math symbols](https://practicaltypography.com/math-symbols.html)

- For light math, use the plus sign (+) and equals sign (=) as usual and the en dash (–) as a minus sign.
- For multiplication or beyond, use real math symbols (×, −, ÷), not alphabetic characters (12 × 34 − 56, not 12 x 34 - 56).
- Use the multiplication sign in dimensions (8.5″ × 14″, not 8.5″ x 14″).

### [Ligatures](https://practicaltypography.com/ligatures.html)

- Ligatures are mandatory only when f and i actually overlap; turn them on to correct collisions.
- Check the fi combination in bold and italic styles too.
- Otherwise ligatures are a stylistic choice; the author keeps them off unless characters collide.
- In CSS, enable the OpenType `liga` feature and/or `text-rendering: optimizeLegibility` (preferably both).
- Don’t insert ligatures manually; they confuse spell checkers, hyphenation engines, and search indexers.

### [Ligatures in programming fonts: hell no](https://practicaltypography.com/ligatures-in-programming-fonts-hell-no.html)

- Don’t use ligatures in programming fonts: they’re “a terrible idea” that misrepresent code or confuse readers, conflict with Unicode symbols, and are guaranteed to be semantically wrong sometimes.
- A good ligature should resolve a collision without drawing attention; avoid gratuitous ones like the default Th ligature in many Adobe fonts.
- When applying automatic curly quotes, don’t convert foot and inch marks; they should stay straight.
- It’s fine to redesign individual characters in programming fonts for disambiguation (e.g., distinguish l from 1 and 0 from O, as in Triplicate’s Code variant).
- Never “prettify” code so one character looks like another.
- When preparing code for others to read, skip the ligatures.
- In code samples, don’t let curly quotes replace backticks or straight quotes (a common LaTeX error), especially in languages that accept UTF-8 input.
